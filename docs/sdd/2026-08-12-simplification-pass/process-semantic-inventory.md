# Agentic Development Process Semantic Inventory

Basis: repository state `f47ff7ddb90bec1bbc6ec76af765fef70a3fab8c`, before the clean-slate rewrite.
This inventory is the semantic checklist for FRD R3.4. It records operative process contracts, not
the current prose that happens to express them.

## Scope and method

The inventory covers `agentic-dev-process` and the process surfaces it directly coordinates:

- always-on `development-process`, `development-principles`, `github-input-trust`, and
  `operator-authority` rules;
- `sdd`, `integration-testing`, `agw-test-env`, and `saga-lead` skills; and
- `agentworks-dev`, `agentworks-reviewer`, and `agentworks-tester` role definitions.

It does not restate the reviewer's product-specific checks, the test environment's operator
inventory, or the SDD artifact schemas. Those remain owned by their existing specialist artifacts;
the inventory records only how the top-level process composes with them.

Each row has one future canonical owner. A consumer may repeat the actor-specific consequence of a
contract, but never redefine the contract. Dispositions mean:

- **Keep**: retain compactly in the current owner.
- **Move**: relocate the contract to the stated owner and replace old copies with a named pointer or
  actor-specific consequence.
- **Merge**: collapse several compatible copies into one contract.
- **Adapt**: retain the invariant while moving harness-specific realization out of universal text.
- **Drop**: remove non-operative history, evidence, or implementation trivia.

## Structural decisions

| ID        | Decision                                                                                                                                                         | Reason                                                                                                                                    |
| --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| STRUCT-01 | The core skill contains only the end-to-end state machine and its branch conditions.                                                                             | Selecting the skill should not load every delivery and delegation edge case before that branch is active.                                 |
| STRUCT-02 | Create skill-local `references/delegation.md` and `references/delivery.md`.                                                                                      | These are cohesive conditional protocols used by several actors; Rulesync copies skill-local companion files to each target.              |
| STRUCT-03 | Move scope discipline and finding materiality into `development-principles`.                                                                                     | Both bind every author and reviewer, not only a session that happened to load the process skill. This removes two unstable numbered APIs. |
