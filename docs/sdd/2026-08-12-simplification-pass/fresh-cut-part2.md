# Fresh Cut, Part 2: the 20 mixed-basis files, re-derived

[sweep-inventory.md](sweep-inventory.md)'s Basis section records that 128 non-group-1 rows across 20
files were lifted from a mixed basis and may name the wrong test, and rules that those files'
non-group-1 rows are re-derived whole rather than audited row by row. This file is that
re-derivation.

**It is a working artifact and dies with the sweep**, on the same terms and for the same reason as
the map: its rows are meant to be merged into the map at integration and then executed, and a
several-hundred-row ledger that outlives its purpose is exactly what this pass exists to remove.
Nothing outside this directory should link to it.

**Derived at `3c6e6d92`** (branch `docs/sweep-map-fresh-cut`, whose base is main `c310d05b`), by
reading every test in the 20 files and deciding every assertion the criteria reach. Nothing here was
carried forward from the settled map's cells: where a row keeps its id, the id and usually the
disposition survived because the re-derivation reached the same answer, and the anchor was written
fresh from the AST at `3c6e6d92`.

The criteria are the always-on `no-prose-policing-tests` rule as generalized by FRD R1.2, plus
[hla.md](hla.md)'s doctrine 1 (validate at boundaries, trust the interior), doctrine 2 (tests assert
behavior, agreement is derived), its source-guard split, and its borderline rubric. FRD R2.2 bounds
every row: no row proposes a new production type or a shipped-contract change, so where preserving
an assertion would need a production discriminator the row is `delete` and the coverage goes with it
(R2.4). One further criterion, supplied by the effort lead and applied throughout: the suite runs on
`windows-latest` in CI at HEAD, so a test guarding a platform-conditional path is CI coverage rather
than inert generality.

**Group 1 is not in this cut.** `match=` sites under `cli/tests` and `assertRaisesRegex` sites under
`website/tests` are the estate `sweep-screen.py generate` derives, and they are owned elsewhere. The
group-1 and deferred group-1 rows that live in these files (G1-015, G1-061, G1-074 to G1-077,
G1-087, G1-100, G1-101, G1-156, G1-K10, G1-K11, G1-K23, L-018, L-021, L-022, L-402, L-403) are named
here only where a row of mine sits beside them.

## Anchors

Every anchor in this file is a `path::qualname` span anchor. None is a line anchor, deliberately:
the defect this cut exists to repair is a number read at one tree and lifted at another, and a span
anchor cannot repeat it. Where a row addresses one assertion inside a test rather than the whole
test, the shape and justification columns say which assertion, quoting its text so a reader finds it
after the lines move. Several rows therefore share one span anchor, which the map's grammar allows
and which column 3 disambiguates.

Every anchor was verified to resolve at `3c6e6d92` by appending these rows to a scratch copy of the
map and running `resolve` over it: **266 anchors over 189 rows, every one `resolved`**, none `gone`,
`grown`, `shrunk`, `retargeted`, `file-gone` or `line-anchored`.

One thing the check surfaced that the lead needs before integration: **`sweep-screen.py` cannot read
a `P2-` id.** `sweep_screen/inventory.py`'s `ROW_ID` accepts `[A-F]`, `L`, `RB` and `G1` prefixes
only, so a `P2-` row is not recognized as a row at all and every command skips it silently, which is
exactly the failure mode that regex exists to prevent. The verification run therefore mapped
`P2-0NN` onto `F-9NN` for its duration. Renumbering these 51 rows into the map's own id space is
part of integration; splicing them verbatim would hand `attribute` and `totals` a short map that
still reports success.

coverage claim: where the settled map's justification made one, the claim was either re-checked, or
dropped and the row re-justified on grounds that do not need it.
