## Additional native observations

These were bounded isolated-HOME probes of the installed native tools against a dummy local
provider. No real inference, operator credentials, backend, SSH or source mutation was used.
Requests were filtered to the measured fixture fields, then owned processes, state and listeners
were removed and cleanup independently checked. Accepted flags and files alone were not treated as
native availability.

- **Codex 0.167.0 outer personas:** exact current user TOML was advertised twice in native
  `multi_agent_v1.spawn_agent`'s `agent_type` description. Project TOML was advertised twice in
  independent valid Git fixtures after ordinary native project trust. Built-in roles were present;
  an undefined control was absent. An untrusted valid project omitted that selector. No role table
  or feature toggle was added. Two initial invalid-Git fixtures were discarded from the project
  verdict. Native project trust is now stated in the permanent artifact guide.
- **Codex 0.167.0 genuine interactive resume:** a native-generated thread seeded by an intentionally
  failed local exec turn was resumed twice through a PTY with `codex resume <id>`, normal strict
  config and the current renderer's changed developer-instruction argument. Both requests retained
  initial developer guidance and omitted current guidance while containing the new input. This
  establishes a concrete same-thread counterexample, not behavior for every version, picker or
  completed/TUI-seeded conversation. The separate session-persona selector evidence remains a
  different observation.
- **Grok 1.0.77 genuine interactive resume:** a successful synthetic SSE seed produced native
  persisted state. Actual interactive `grok --resume <id>` received the current renderer's changed
  rules argument and new PTY input. Its request retained initial system guidance and omitted current
  guidance. This exact interactive case was measured once. It used neither a headless resume nor a
  fabricated session file and does not establish every native mode/version.

The earlier exploratory Grok fixture returned JSON to a streaming request, causing retries and 13
captures against its 10-request internal ceiling. That overrun is retained as a test-control
failure, not clean acceptance. Separate exact-mode probes used bounded valid/intentional-error
responses and stayed within their new limits. No failed native fixture termination is presented as a
successful model turn.

## Remaining decision

Passing current arguments on every process launch does not establish that a resumed conversation
uses changed guidance. The current native-resume claims therefore cannot be checked off or used to
lock this SDD. The proposed conservative disposition is to warn and leave session hints/rules
unhandled on genuine Codex/Grok resume, directing the operator to `--force-new` for delivery into a
fresh conversation. Investigating another explicit resume mechanism is a different possible
direction. The operator's decision is pending; no support-matrix narrowing or dependent product
change is recorded as approved here.
